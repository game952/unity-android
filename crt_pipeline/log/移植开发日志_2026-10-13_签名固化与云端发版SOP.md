## 云端发版 SOP（以后每次发新版照此四步，命令整段可粘贴）

### 步骤 1 · 提交并推送
    cd /storage/emulated/0/Game/游戏端 && git add -A && git commit -m "更新说明" && git push

push 自动触发「② 打包 Android APK」

### 步骤 2 · 等 Actions 变绿
GitHub → Actions → 「② 打包 Android APK」，黄圈 → 绿勾，约 20 分钟
（日志/文档类提交也会触发构建，属正常，取最新 run 的产物即可）

### 步骤 3 · 下载 APK
该次运行页底部 Artifacts → 下载 MyGame-Android → 解压得 APK

### 步骤 4 · 覆盖安装 + 验收
- 手机直接安装新 APK（签名一致，无需卸载，存档无恙）
- 进游戏验收目标资源（如 a_wt_m_clo_02_01）

## 排错对照表
| 症状 | 根因方向 | 动作 |
|---|---|---|
| 构建红，报 Keystore was tampered with, or password was incorrect | Secret 粘贴不完整/有误 | 核对三个 ANDROID_KEYSTORE_* Secret（b64 应 3596 字符） |
| 构建红，License 相关 | 激活风控/账号密码改动 | 核对 UNITY_EMAIL/PASSWORD；v6 账号激活运行 #4 已实测可用 |
| 构建绿但 Artifacts 没有 APK | 产物路径不对 | 检查 yml 上传步骤 path=build/Android/**/*.apk，截图发助手 |
| 覆盖安装仍提示签名不一致 | 装的还是旧 debug 包 | 确认装的是本次 Artifacts 解压出的新包 |

## 换机 / 灾备
- 从备份恢复 mygame-keystore.b64 → 重新填三个 ANDROID_KEYSTORE_* Secret 即可
- 严禁重新生成 keystore（签名一变，全量用户无法覆盖安装）
